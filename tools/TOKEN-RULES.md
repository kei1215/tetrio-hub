# トークンを無駄にしないための決まり

## いつ整理するか
| タイミング | やること |
|---|---|
| 作業を1つ終えたとき | HISTORY-AND-REGRESSIONS.md に1〜2行追記する。一時ファイルを消す。memory には、コードや履歴から分からないことだけを書く |
| 話題が変わるとき | 会話を新しくする。引き継ぎは長い会話ではなく md ファイル(伝言・履歴・やること)で行う |
| 会話が長くなったとき(要約が出始めたら) | 今の状態を md に書き出して、新しい会話へ移る |
| 毎晩の2回目の作業の最後 | memory を整理する。古い経緯は HISTORY へ移し、memory には今も有効な事実だけを残す。MEMORY.md の索引は1行ずつにする |
| 週に1回 | 終わったサイドセッションをアーカイブする(ユーザーの了解を取ってから)。all-tetrio-patch には最新のリリースフォルダだけを残す |

## 作業中の決まり
- tetrio.js・client.js・まとめたバンドルのような大きいファイルは、丸ごと読まない。grep か行の範囲で読む。
- コマンドの出力は head・tail で短くする。ログを全部貼らない。
- パソコン全体を検索しない。探すのは ~/Downloads/tetrio-hub、all-tetrio-patch、tetrio-replay-video の中だけ。
- サイドセッションは本当に必要なときだけ作る。1つの作業につき1つにする。
- 返事と報告は短くする(ユーザーの希望)。
- 同じ調査を繰り返さない。分かったことは HISTORY か memory に1行で書く。
