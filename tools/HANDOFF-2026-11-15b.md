## 1. ブラウザ版 OFFLINE が起動しない件 → 公開済み (commit ea6ab66)
- 症状
  - 通常版:「OFFLINEを起動できませんでした。TETR.IO本体が更新されています。」
  - AI 版:黒い画面に「終了」ボタンだけ出る。
- 調査結果
  - tetr.io 本体は更新されていない。tetrio.js は SHA 1244839b…、2553112 bytes で v4.8255 の client.patch.json と一致した。v4.8255 のローダーで本体チェックを通ることも確認した。
  - 原因は古いブックマーク。
    - offline-v4.8213〜4.8241 は古い本体の SHA(9e57… / f203…)を前提にしていたため、不一致になった。
    - AI 版は 5.06 公開時に offline-va5.05 を `git rm` していたため、5.05 のブックマークが 404 で黒画面になった。
- 対応
  - offline-v4.8213/14/16/35/38/39/40/41 を v4.8255 の中身で上書きした(rsync)。standalone-loader.js だけは各フォルダ自身のものを残している。
  - offline-va5.05 は va5.06 のミラーとして復活させた(ローダーは 5.05 のもの)。
  - 互換性の確認:client.patch の形式(ops, sourceSha256 …)とテンプレートの `__CLIENT_BLOB_URL__` 置き換えは全版で同じ。テンプレート内のスクリプトは offline-v4.8255 への絶対 URL。
  - 公開を確認済み:4.8239 の client.patch.json は 1244839b。va5.05 のローダーは 200。
- 未確認:古いブックマークで実際に起動するところ。アプリ内ブラウザから localhost に接続できず、テストできなかった。ブックマークレットは起動コードを最大30日キャッシュするので、直らない人には再登録を案内する。
- **今後のルール**:リリースや再ビルドのたびに、古いフォルダを最新版でミラーし直す。古い offline-va* を `git rm` しない。

## 2. 「configのハンドリング以外の設定がオフラインで維持されない」→ 調査途中・未修正
- オフライン本体は vO の O/offline/client.js で、設定は `ot` オブジェクト。
  - 保存:`mt()` が localStorage の "userConfig" に、既存値と ot を深くマージして書き込む(`qpCfgMerge`)。
  - 読み込み:`gt()` が "userConfig" から読む。
  - setFrameLimit も 'userConfig' に書き込んでいる。
- 注意:ブラウザ版は blob:https://tetr.io で動くので、本物の tetr.io と localStorage("userConfig")を共有している。本物の tetr.io を開くと上書きされている可能性がある。
  - 仮説:本物は新しいスキーマで、ハンドリングだけ形式が共通なので残る。
  - 他に、gt() が一部のキーしか ot に反映していない可能性もある。
- 方針案:オフライン専用のキー(例 `qp-offline-userConfig`)に保存して、そこから読むようにする。
  - メモリにある「ユーザーの tetr.io userConfig に書かない」制約にも合う。
  - 実機で、CONFIG を変更 → 終了 → 再起動しても値が残るかを確認すること。
